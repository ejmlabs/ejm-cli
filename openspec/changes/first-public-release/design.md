# Design

## Trust split

The build workflow never writes to the repository. Its jobs run project code (cargo build scripts and proc-macros), so they get `permissions: contents: read`, no secrets, pinned actions and `--locked`. The harness is checked out at the revision in `.github/harness-revision` with credentials not persisted. Attaching files to a draft release belongs to a separate shared workflow with `contents: write` that runs no project code and recomputes every digest. That workflow is a separate change in the `.github` repository, so this change only defines what it receives.

## Artifact contract

Each build job uploads its own artifact (`build-linux-x86_64`). The `collect` job downloads them into one directory, writes one combined `build-sha256.txt` in `sha256sum` format and uploads the directory as the single `release-files` artifact. It holds only regular files at its root:

- `ejm-cli-<version>-<platform>.tar.gz`, holding one top directory of the same name with `ejm-cli`, `LICENSE`, `THIRD_PARTY_NOTICES.md` and `HARNESS_REVISION`.
- `build-sha256.txt`, one line per release file.

Platforms are `linux-x86_64` now and `macos-arm64` after notarization. Names avoid the source assets the draft flow already creates. The version is read from `VERSION` and must equal the workspace version. The job records `GITHUB_SHA` in its summary. The shared release workflow checks that the build run's commit equals the tagged commit.

## Shared pin

`pr.yml` and the native `release.yml` pin `ejmlabs/.github` at `451ef7d1ef46373b6018a1fbcacc331e15e1d093`, the squash merge of the reviewed revision `81073b4673ebefb99d6adaa649166b642091427a` (identical tree) that adds the verify and attach workflows. `release.yml` is generated byte-exact from `consumer_workflows(revision, native=True)` at the pinned commit, and `build.yml` passes that commit's `native_build` check. The shared standards check does not use `.github/review-context`, so it is left as it was.

## Order and commit

Build and smoke run on the main commit that the draft release later tags. A failed smoke check fails the job and no artifact is uploaded.

## Linux baseline

The archive links `libdbus-1` dynamically and needs the build runner's glibc. The job builds on `ubuntu-24.04`, so the minimum is glibc 2.39 (Ubuntu 24.04 or Debian 13 or later). Debian 12 and Ubuntu 22.04 fail at launch with the loader's own message. Stored credentials need a session D-Bus and an unlocked Secret Service; without one the program still starts and `--replay` works.

## macOS waits for notarization

`build.yml` has no macOS job yet; a comment marks where it goes. The release notes list no macOS download. Nothing says the build is signed or notarized until a recorded run exists.

## Smoke check

`ejm-cli --version` must print the `VERSION` value, and `ejm-cli --replay run "Hello"` must exit 0 with output. The job runs both against the unpacked archive in a fresh directory with an empty `HOME`.

## Issue forms

Forms carry a `version` and a `platform` field. Visitors reach them from the release notes by URL; nothing is prefilled with visitor data. The security link stays the private advisory URL.
