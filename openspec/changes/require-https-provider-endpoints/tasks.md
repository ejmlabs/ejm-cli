## 1. Reject non-loopback HTTP before the API key is read

- [x] 1.1 Add `require_https_or_loopback` in `crates/ejm-cli/src/endpoint.rs` and call it from `Args::api_base_url()` in `crates/ejm-cli/src/args.rs`. `api_base_url()` returns `Result<&str>` for the effective base URL (`--base-url`, otherwise `EJM_CLI_BASE_URL`, otherwise the existing https default). The helper parses with the `url` crate, does not resolve DNS or open a socket, and does not name `--base-url`, so a later `--registry` flag can reuse it. Accept `https` when a host is present. Accept `http` only when `url::Host` is ASCII case-insensitive `localhost`, an IPv4 address with `is_loopback()` (`127.0.0.0/8`), or an IPv6 address with `is_loopback()` (`::1`). Reject `0.0.0.0` and private LAN addresses as cleartext. Return `invalid provider base URL. Change --base-url or EJM_CLI_BASE_URL.` when the value does not parse, has no host, has no scheme, or uses a scheme other than `http` or `https` (`ftp`, `file`, `ws`). Return `provider base URL must use https, or http on a loopback host (localhost, 127.0.0.0/8, or ::1). Change --base-url or EJM_CLI_BASE_URL.` for non-loopback `http`. The stderr error must not include the raw URL, its userinfo, or the API key. Do not add a length cap, rewrite the URL, or add a bypass flag.
- [x] 1.2 In `crates/ejm-cli/src/main.rs` `provider()`, call `api_base_url()?` for OpenAI-compatible and Anthropic providers before `required_api_key()` and before `OpenAiProvider::new` or `AnthropicProvider::new`. Keep the `responses` and `chatgpt` fixed-endpoint check ahead of this rule. Do not call the validating method from `--replay`, `--replay-file`, session listing, or `--package-provider`.
- [x] 1.3 In `doctor()`, for OpenAI-compatible and Anthropic providers, call `api_base_url()`. When the URL is accepted, print it on the `Endpoint:` line as the usable endpoint. When it fails the HTTPS rule, print an `Endpoint:` line that contains the configured URL, marks it rejected, and says HTTPS is required except for loopback hosts, then exit 1. Do not print the API key, and do not present that URL as usable. If the URL has userinfo, omit the userinfo from that line and still show the host. When the URL is invalid, exit 1 with the invalid base URL error. Leave `responses` and `chatgpt` doctor output unchanged.
- [x] 1.4 Update the `--base-url` help text: https is required, http is limited to a loopback host, and ChatGPT and Responses keep their fixed official endpoint.
